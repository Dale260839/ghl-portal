## 5 · Anything that surprised you

**Two live bugs, both found by looking rather than by a failing test.**

**Eleven of fourteen portal screens showed every homeowner "No project".**
`currentPortalProject` resolved a client only via
`listProjectsForContact(session.contactId)`, guarded by `contactId !==
undefined`. That handles one of the two kinds of homeowner. Since the code
sign-in deliberately mints no contact id, it is now *every* homeowner — they
signed in successfully and found an empty portal that reads as "your
contractor hasn't shared anything" rather than as a fault. Found while tracing
per-project access for task 2, not by any test.

**Editing a milestone's dates wrote to the wrong columns.** `createMilestone`
writes `planned_start`/`planned_end`; `updateMilestone` wrote
`target_date`/`completed_date` — the pair migration 0001 created and 0003
superseded. So an edit appeared to work and changed nothing on screen. Worse,
the end date landed in `completed_date`, giving a milestone nobody had
finished a completion date a report would take at face value.

**And one of my own tests passed for the wrong reason.** "An unsigned project
admits nobody" used a contractor lookup that refused, so it stayed green when
I deleted the signature gate — it was refusing for the wrong reason entirely.
Only caught by deliberately reintroducing the bug. Same lesson as the two
vacuous guardrails last week: a green test proves nothing until you have
watched it go red.
