## The publishing path is now code

§3.2 — field submits → PM reviews and edits → PM publishes → client sees — was
a screen behaviour this morning. It's four workflows and an executor now.

**WF1 — New Project Setup.** All ten §11 actions. Refuses a handoff payload
without a valid shared key rather than inventing one. Idempotent: a re-fired
handoff records activity instead of duplicating milestones. Flags an unassigned
PM loudly — an unassigned project has nobody to receive the review queue, which
quietly breaks the approval path.

**WF2 — Project Stage Sync.** Refuses to act without the shared key rather than
falling back to name matching (§3.6 forbids exactly what a helpful implementation
would do here). Rejects stages outside the §7 pipeline. No-ops on a re-fired
webhook. **On Hold and Canceled do not move the progress bar** — a project paused
at 65% has not regressed to 0.

**WF3 — Field Update Submitted.** Sets `Pending`, queues for review, notifies the
PM, raises an Issue on a blocker (Urgent + `Safety Concern` when flagged), sets
client-action when a decision is needed. Notifies the client of **nothing** —
there's an explicit test asserting the absence of all four client-facing effects,
because that is precisely what a well-meaning change adds later.

**WF4 — Field Update Approved.** The only path in the system that makes an update
client-visible. Refuses to fire on `Approved Internally`, refuses to publish an
empty summary, respects the portal master switch at publish time. Internal notes
aren't filtered out — they are never passed in, so no refactor can leak them.

**Executor + ports.** Handlers are a mapped type over the effect union, so adding
an effect without wiring it is a compile error rather than a silent no-op found
in production. On failure the executor stops and reports **which effects already
landed** — "created the project and associated the contact, then failed seeding
milestones" is actionable in a way "WF1 failed" is not.

**The demo runs through them.** Submit and Approve-and-Publish now execute the
real workflows via fixture-backed handlers, not a parallel path that happens to
look similar. The field form gained blocker and client-decision inputs so WF3's
branches are reachable.
