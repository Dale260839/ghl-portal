## WF1 + WF2

Built as pure planners: trigger in, typed effects out. No network, no clock, no
credentials. D-002 moved the workflows out of GHL's builder into code, but §11 is
still the specification — this shape lets each action be asserted against it
directly, so "does WF1 set progress to 10%?" is a unit test rather than a
click-through in a live sub-account we don't have access to yet.

**WF1 — New Project Setup.** All ten §11 actions. Refuses a handoff payload
without a valid shared key rather than inventing one. Idempotent: a re-fired
handoff records activity instead of duplicating seven milestones and two tasks.
An unassigned PM is flagged loudly — an unassigned project has nobody to receive
the field-update review queue, which quietly breaks the §3.2 approval path.

**WF2 — Project Stage Sync.** Won't act without the shared key rather than
falling back to name matching (§3.6 forbids precisely what a helpful
implementation would do here). Rejects stages outside the §7 pipeline. No-ops on
a re-fired webhook so a client isn't told twice about the same stage. **On Hold
and Canceled do not move the progress bar** — a project paused at 65% has not
regressed to 0, and showing that to a homeowner would be alarming.

**88 tests green** (54 web, 34 contracts). Build clean.

## Three gaps in §11 this surfaced

All isolated in `workflows/defaults.ts` as provisional tables, recorded as W1–W3
in `KICKOFF.md` §5. Each is a one-table edit once Chris confirms — none blocked
the build, and none are guesses pretending to be spec.

| # | Gap | Current |
|---|---|---|
| **W1** | WF2 must "update Progress Percentage" — **no mapping given** | Straight line anchored on the two figures §11 does state: 10% at creation, 100% at Completed |
| **W2** | WF1 must create "default milestones/tasks" — **neither list exists** | Seven milestones, two tasks. Thin on purpose — a wrong default task on every project is noise a PM clears by hand |
| **W3** | WF2 notifies the client "**when appropriate**" — undefined | Six stages, biased toward silence. Over-notifying gets a portal muted, and then the notifications that matter are missed too |
