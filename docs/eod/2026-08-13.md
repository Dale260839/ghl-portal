## The leak

The live database has **43 active projects across 5 different contractors**, and
every read returned all 43 to whoever was signed in. Found by checking which
column actually owns a project rather than assuming.

Fixed, and fixed the same way the client gate is — structurally:

- `TenantScope` is a **required first argument** on every read. There is no
  unscoped overload to reach for, so forgetting to scope is a type error rather
  than a leak. The compiler found all sixteen call sites; I didn't have to.
- `assertScope` **fails closed**. An absent or blank scope raises, because the
  natural fallback for a missing tenant filter is the entire database.
- The filter is built **inside** the reader from the asserted scope, never passed
  in — a caller that can supply its own filter can supply none.
- A lookup **filters before matching**, since found-then-rejected is one refactor
  away from found-then-returned.

**Clients are deliberately not tenants.** A homeowner's projects can sit with any
contractor, so `scopeOfProject` derives the scope from a project they were already
authorized to see — and it takes a whole `Project` rather than an id, so only
someone already holding one can call it.

**Verified against production and fixtures:** Marcus sees BSP-177/184/191, Priya
sees BSP-168/203/212, zero overlap. Issues follow their projects — Priya's list is
correctly empty. On the live BuildSuite screen: 26 projects vs 6, no overlap.

**Also fixed: the data source was a module-level singleton.** One instance per
process, with one deployment serving many sub-accounts, means the first tenant's
source serves the second. Now keyed by location, and a configured-GHL request
with no `locationId` throws rather than guessing which sub-account to read.

## Three decisions

**D-011 — auto-login from GHL.** The Hub becomes a GHL **Custom Menu Link**, the
same pattern BuildSuite already uses. A user signed in to GHL is signed in to the
Hub; GHL hands us location and user context on landing and we mint our own session
on our own domain.

**This dissolved the blocker.** We don't need `bs_session`, so we don't need a
`.buildsuite.ai` subdomain, so the Hub can live at `projects.<contractordomain>`
exactly as §2 specifies. The browser rule that made D-006 and §2 incompatible
simply stops applying. The landing context also supplies the tenant key — so
auto-login and per-contractor scoping are one piece of work, not two.

**D-013 — the Hub is multi-tenant.** Premium clients each have their own
sub-account and must be able to move between them. One deployment, many locations
— which invalidated `GHL_LOCATION_ID` as a single env var. Location is now
per-request; the var is renamed `GHL_DEV_LOCATION_ID` and labelled a development
convenience.

Tenancy is two-dimensional now: `locationId` scopes GHL reads, `auth_profile_id`
scopes BuildSuite reads, and neither may fall back to "all".

**No switcher needed.** Contractors already switch sub-accounts inside GHL; with
an agency-level menu link each landing carries its own location. The requirement
isn't "build a switcher", it's "never cache across locations" — narrower and
testable.

**One deliberate refusal:** the development token resolver **rejects** any
location other than the one it's configured for. Returning the build token for
anything asked would work perfectly with one sub-account and cross tenants the
instant there were two.

## WF7 + Issues screen

WF3 has been raising an issue on every reported blocker and **nothing displayed
it** — worse than not raising one, since the field user is told it was logged and
the PM never sees it.

WF7 assigns a readable issue number, notifies the PM, and **confirms back to the
reporter**. That last one isn't ceremony: someone who reports a hazard and hears
nothing assumes it went nowhere, and the next hazard goes unreported. Safety
concerns escalate *and* always get a remediation task, whether or not the reporter
asked — "someone will look at it" is not a plan.

An unrecognised §6.7 category is **refused rather than coerced to Other**, because
coercion would silently swallow a mis-typed "Safety Concern" — the one case where
it matters most.

The screen shows internal notes and the client update side by side, which is what
makes the distinction obvious to whoever writes them.

The `EffectHandlers` mapped type caught all four missing WF7 handlers at compile
time. That design paying for itself.
