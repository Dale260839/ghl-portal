## 1 · Navigation: Projects is a parent, and a section asks which project

`8143e7c`, `561e8d6`

**Projects now holds the project's own sections** in the sidebar: Overview,
Timeline, Schedule, Daily Updates, Designs & Selections, Budget, Change Orders,
Documents, Photos & Videos, Messages, Issues, Payments, Completion, Visibility
and the new People — fifteen in all. They are open by default; the chevron
folds them.

**Eight flat sidebar entries are gone.** Schedule, Designs & Selections,
Estimates & Budget, Change Orders, Documents, Messages, Punch List and Settings
each pointed at the *first active project*, whichever one you were looking at.
Each page now appears once, under its project.

sidebar, twice. Overview moved into the sidebar as the first section, so there
is still a way back to a project's summary.

**Clicking a section with no project open now asks which project.** It used to
open the first active project silently. It now opens the Projects list in
chooser mode (`/dashboard/projects?open=timeline`): a banner saying *Choose a
project to open its Timeline*, with Cancel; every row opens that section; the
Awarded / Draft / All pills keep the choice; the section stays lit while you
choose.

One list (`lib/project-nav.ts`) drives the sidebar and the chooser, and a test
fails if a section has no page behind it.

## 3 · The sidebar sections were nearly invisible

`badc862` — *"the color is off"*

The sections rendered navy on navy. They used `navy-300`, and the theme never
defined 300 or 500. Tailwind silently outputs nothing for an undefined shade, so
the text fell back to the body colour.

It was never only the sidebar: **76 class uses across 30 files** named those two
shades. On light screens they fell back to a darker colour, which is why nobody
noticed. Fixed once, in the theme, with shades chosen by measured contrast:

| Shade | Value | Contrast |
|---|---|---|
| `navy-300` | `#7a95c6` | 6.0:1 on the sidebar, 3.0:1 on white |
| `navy-500` | `#3f629b` | 6.1:1 on white |

A guardrail now fails on any shade that is used but not defined.

## 5 · One sign-in page for everyone

`45ed7c6` — *"only one login route, backend checks whether it's the homeowner,
contractor or field crew, but the auto log-in from BuildSuite should persist"*

`/` is now the only sign-in page: an email, and one field labelled **Password or
project code**. Nobody picks a role; the server decides from what was typed.

| Who | How they get in |
|---|---|
| **Homeowner** | Email on the contract + project code (`BSA-053`; `bsa 53` also works). Same check as before: signed contract required, 5 tries an hour. |
| **Field crew** | Email + the password they set from their invitation. Now limited to 10 tries per 15 minutes — **it had no limit before.** |
| **Contractor** | Unchanged: open the Hub from the BuildSuite menu in GoHighLevel, signed in automatically. Checked on prod today. |

- Every wrong-credential failure shows the same message, so the page cannot be
  used to learn whose email or contract is on file.
- A bad GoHighLevel link now shows its reason on the sign-in page; before, the
  reason was dropped.
- `/signin`, the old homeowner page, redirects to `/`, so links in emails already
  sent still work. The signature email can point at the site root from now on.

**A security hole this closed.** The old page listed demo identities (Marcus,
Priya, Tony, Dana) as buttons that signed anyone in **with no password, under
real BuildSuite profiles** — on the public site, into real client names,
addresses and emails. They are gone from the page and work only on a developer's
machine with `ENABLE_DEMO_SIGNIN=true`. **That flag must never be set on
Vercel.** Anyone who used those buttons to reach the contractor view should use
the GoHighLevel menu link instead.

**Checked:** 15 new tests, plus 15 bugs reintroduced on purpose and each caught
by the test meant for it. In a browser: desktop and phone layouts, the error
display, the demo flag on and off. On prod: the new page, the old demo list
gone, both redirects, and the contractor auto-login landing on the dashboard.

**Please try on prod** — steps 1, 2 and 4 in a **private window**. A browser
