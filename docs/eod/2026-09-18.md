## 1 · Photos show wherever they belong — `8032f46`

Every photo on a project already reached the Photos list, whoever added it; a
crew photo from a task or an update is a row on the same project and nothing
filtered by uploader. What was wrong was what the lists *showed*.

- **Your Photos & Videos** now shows each photo as a picture, with who added it
  and whether the client can see it.
- **The crew's Photos screen** shows thumbnails.
- **The homeowner** saw a grey box reading "Photo" and a dead "Download" button
  on documents. Both now work: released photos appear as images they can open,
  and released documents download.

**Why it was broken:** files were served only by storage path, which needs a
contractor's identity. A homeowner has none, so their files could never load.
Files are now served by row id as well, and for a homeowner the row is read
through the portal's own gates — the portal switch, the section switch and
`client_visible`.

**Checked** against a local build serving real image bytes: the released photo
loads for contractor, crew and homeowner; the internal one is absent from the
portal, answers 404 for the homeowner, still opens for the contractor; signed
out gets 401.

## 2 · Email sends with the sub-account's own token — `9f18cdb`

Invoices were fixed for this yesterday; email was not. It swapped in the
session's location but kept the single default token, so the moment sending was
turned on, everything for APS would have failed with 401 — invitations,
password resets and the new appointment emails. `getGhlEmail` now takes that
location's token from `GHL_LOCATION_TOKENS`; with no entry the default token
stands, so AFC is unchanged. A guardrail holds all three cross-tenant callers
to it.
