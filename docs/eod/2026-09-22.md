## 3 · The agency install — `b9ef72a`, `c4e9b95`

**What is wrong today.** A Private Integration token only opens the sub-account
it was made in — measured on 17 Sep, each of our two tokens gets `401 This
location is not accessible from this token!` on the other's sub-account. So
every new contractor is a manual step: create a token, paste it into
`GHL_LOCATION_TOKENS`. Forget it, and their invoices fail with nothing to say
so.

**What is there now.** Migration 0016 (one new table), the install flow at
`/api/connect/start`, agency token refresh, the per-sub-account token
resolver, and eight call sites moved onto a single decision point.

It fills a seam that has been waiting since August. `lib/ghl/location.ts`
declared a `TokenResolver` with `kind: 'development' | 'oauth'` and a comment
saying the OAuth one would land and nothing above it would change. It did, and
nothing did.

## 4 · Built to be switched off

This is the part worth reading twice, because it is what the day was actually
about.

`configForLocation()` computes **today's answer first** — the per-location
Private Integration token — and keeps it unless the Marketplace install produces
something better. So:

| | What a request uses |
|---|---|
| The flag unset | The PIT. Byte for byte yesterday's behaviour. |
| Set, app half-configured | The PIT. A typo must not take everyone down. |
| Set, Hub unreachable | The PIT, with a warning. |
| Set, 0016 not run | The PIT, with a warning. |
| Set, not installed on that sub-account | **That contractor's own PIT**, warning naming the location. |
| Set, install healthy | The minted token. |

A test asserts the switched-off case against `withLocationToken` *itself* rather
than a copied expectation, so if the old path ever changes the test follows it
instead of going stale.

**The rollback is `docs/ROLLBACK-GHL-OAUTH.md`**, four levels deep: unset one
variable and redeploy; revert the commits back to the tag; drop the table;
uninstall from GoHighLevel. Level one covers every fault this change can cause
and takes about a minute.

## 5 · The hazard, and what was done about it

GoHighLevel rotates the refresh token — every refresh returns a new one and
kills the old. On a platform running many instances at once, two simultaneous
refreshes leave one instance holding a dead credential, and that credential is
now *everyone's* API access rather than one contractor's.

So a refresh is claimed in the database first, and only the winner calls
GoHighLevel. Same single-winner pattern as the invoice claim in 0014, with one
difference: this claim **expires**. A crashed refresh must not lock the agency
out for ever, and a duplicate refresh costs a wasted token where a duplicate
invoice would cost a homeowner a second bill.

## 7 · One thing deliberately left alone

`lib/data/source.ts` swaps in the session's location while keeping the default
token — the exact pattern the guardrail forbids in the other three callers. It
sits behind `GHL_PROJECT_OBJECT_KEY`, which has never been set, so nothing
reaches it and making it async would ripple through every page for a dead
branch. **If that key is ever set, it needs this treatment first**, or it reads
one contractor's location with another's token. It is written into the plan so
it cannot be forgotten quietly.
