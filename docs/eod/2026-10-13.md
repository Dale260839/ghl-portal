# Project Hub — one link, one use, and a tab of your own

**13 October 2026**
**Live at:** https://project-hub-one-vert.vercel.app

> One release today, `2843e90`, built on the verified 9 October production
> commit. Two database migrations come with it, and **the order matters** —
> see the last section.

---

## 1 · An invitation link could be used twice

A crew invitation, or a password reset, did two separate things: set the
password, then mark the link as used. Two steps mean a gap, and in that gap a
link could be redeemed again — two people following the same emailed link, or
one person double-tapping on a slow connection.

Both now happen in a single database transaction. Simultaneous attempts queue
behind each other and exactly one wins; the rest are refused. **A failed
transaction consumes nothing**, so a link is never silently burned by an error.

Once a redemption succeeds, any other pending links for that person are
revoked — an old invitation cannot be dug out of an inbox later.

Proven against a real PostgreSQL server rather than a local stand-in: twenty
simultaneous redemptions of one link, a rollback with another attempt waiting
behind it, and two phones consuming the same link at once. Exactly one claim
succeeded every time.

## 2 · Changing a password now ends the old sessions

Previously, changing a password left anyone already signed in with that account
signed in. The point of a password change is usually that somebody should stop
having access, and it did not do that.

Each membership now carries a credential version. A password change moves it
on, and any older session fails its next read or write.

**Nobody is signed out by this release.** Existing sessions stay valid until
their password changes — this does not rotate anybody's credentials behind
their back.

## 3 · Contractors can open the Hub in its own tab

The Hub lives inside GoHighLevel's frame, which is right for everyday work and
cramped for anything long. A verified contractor can now pop their workspace
out into a standalone tab.

The care is in the handoff, because a link that opens somebody's workspace is a
link that opens somebody's workspace:

- random, single use, and expired within two minutes
- carries the **original** session's deadline and tenant scope, so it extends
  nothing and widens nothing
- travels in the part of the URL browsers never send to a server, and is
  stripped from the address bar immediately
- redeemed by a same-origin request, so another site cannot spend it

It is contractors only, and only ones already verified by GoHighLevel. No crew
or homeowner handoff was added, and no new way to sign in without a password.

## 4 · The homeowner's dashboard was showing the wrong date

It displayed the commercial project's own old date rather than when the
contractor actually published something. A homeowner reading "last updated"
was being told about paperwork, not about their house.

It uses the release date of the published update now. Milestones already passed
are no longer listed as upcoming, and milestones with no date say so instead of
showing something that looks like one.

## 5 · Mobile, continued

The phone headers yield properly and the operator controls stay reachable —
the same ground as Friday, now checked at 320, 390, 768 and 1440 pixels against
the real components, and the production build checked at six widths.

## Verified

1,496 web tests and 40 contract tests, typecheck and production build — all
confirmed here as well as on their side. Real-database contention tests for
every concurrency claim above, all on synthetic records; no production account,
password or client record was touched.

**One note on the build:** this release adds an icon package as a dependency
for a single icon. The build is clean and the package is properly declared, so
nothing is broken — but the icon set in this repo was deliberately hand-drawn
to avoid exactly that, and the new icon does not go through the stroke-weight
rule the others do. Worth a decision rather than a drift.

## What is *not* done, honestly

A live password-reset drill has deliberately **not** been run against a real
person's credentials. The transaction and session-invalidation proofs are
synthetic. Before relying on resets with real crew, one person should do a
genuine reset on their own account and confirm their other sessions end.

Online payments are untouched and still need the contractor's GHL gateway.

## Before this is live — the order matters

Both migrations are additive and work with the previous application, so the
database can safely go first. **The reverse is not true.** The new code calls
database functions that do not exist until the migrations are installed, and
crew invitations and password resets go through one of them.

1. `0023_atomic_credential_redemption.sql` — Project Hub only, never BuildSuite
2. `0024_browser_workspace_handoffs.sql` — same database
3. Confirm Vercel's production deployment is on `2843e90`
4. Then: a fresh GoHighLevel sign-in, open the standalone tab, check the
   session and the projects carry across, and sign out natively

**A Ready preview is not a production release.** If something regresses, roll
back the application and leave the database alone.

And still outstanding from last week, unchanged: **`GHL_SSO_COMPANY_ID`**,
`ADMIN_LOCATION_IDS`, the shared secret that wants rotating, and no backups on
the Hub database.
