Thanks Chris, that unblocks most of it. Three I can act on today and one I want to push back on before I build it.

The shared key, confirmed, and your memory is exact. I measured it this morning. 101 projects, 48 with a project code, all in the BSA-NNN format, all unique, BSA-001 through BSA-048. Half the projects, exactly as you said. That closes the question that has been blocking Sing since the 20th.

One small change it forces on our side. The architecture document specifies a different format that nobody ever implemented, and our code still validates against it, so today a handoff carrying BSA-002 would be rejected. Project code is a real column with real values, so we change to match reality. Half a day and it is ours, not Sing's.

On having Supabase assign the IDs, I agree and I think it matters more than it sounds. 53 projects currently have no code at all. If the database assigns it on insert that gap closes permanently. If it stays application assigned it can reopen any time somebody creates a project by another path. Worth putting to Sing as its own question.

Storage on Supabase, agreed. It is cleaner for a specific reason. GoHighLevel media would put client photos behind a system the field crew is never allowed to touch and whose object model we still cannot read. Supabase sits beside the records that point at it. That unblocks uploads and nothing else is waiting on it.

Payments. That is exactly the right question and I do not want to answer it from memory. GoHighLevel does have invoicing and does have workflow actions, but whether a workflow can create and send an invoice depends on the sub account tier and which API our token can reach, which is the same tier question already sitting with Pat. Let me check it properly against the live account and come back with a yes or no. If GHL can do it, it is the better answer, because the invoice lands where the rest of the operational record already is and there is no second system holding money data. If it cannot, Stripe is straightforward and we trigger it from the same workflow. The screen is deliberately unbuilt so nothing is wasted by waiting a day.

The homeowner login is the one I want to talk about. Your second point is already true and I will put it in writing: a project number alone opens nothing. That is built and tested.

But email plus project code as the whole credential is weaker than what is already in the code, and I do not think it is what you actually want. Here is the arithmetic. The codes run BSA-001 to BSA-048, sequential, no gaps. So the secret half of that pair is a number between 1 and 48. Someone who knows a homeowner's email address, which is not secret, can try all 48 in under a minute and read that homeowner's budget, schedule and documents. It also cannot be revoked, because the credential is the project's identity.

What is already built instead. The contractor invites the homeowner by email, they get a single use link that expires, they set their own password, and the contractor can revoke them in one click. I created and revoked a test homeowner this week to prove it works end to end.

I think we actually agree on the requirement. You want the contractor to control who gets in, and you do not want the homeowner to need setting up in GoHighLevel first. Both are true of the invitation flow. The only difference is what the homeowner holds afterwards, a password they chose rather than a code that is also printed on their paperwork.

If you want the project code in there regardless, the safe version is to ask for it at invitation time as a second factor before they set a password. That gives you the they need their code property without it being a standing password. Small addition, happy to build it.

On the pilot, yes. The system is ready for a real deal in a way it was not last week. A contractor can edit and archive records, invite their crew and their homeowner, and a field update filed on site now persists and only reaches the homeowner after a person approves it. Three things to line up first: Sing's handoff stamp which your key answer just unblocked, Pat's tier answer and webhook secret, and the login decision above since a pilot means a real homeowner signing in.
